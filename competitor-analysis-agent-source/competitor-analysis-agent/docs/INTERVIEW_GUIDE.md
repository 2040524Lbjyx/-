# 项目答辩说明

## 30秒介绍

这是一个面向产品经理的可追溯竞品分析系统。它用 Coordinator、Crawler、Analyzer 和 Reporter 分离任务规划、数据采集、结构化分析和报告生成，并通过字段级来源、Schema 校验和质量门禁，避免把无法验证的 LLM 内容直接包装成事实。

## 为什么不是一个 Prompt

单 Prompt 适合已有文本的总结，但本项目包含官网发现、动态页面采集、并行执行、结构化抽取、失败重试和报告渲染。这些步骤的工具、状态和失败处理不同，拆分后可以独立测试和降级。对于只有一段文本的简单任务，不需要使用多 Agent。

## 为什么选择 LangGraph

项目需要显式保存执行状态，根据错误类型继续、降级或终止。LangGraph比纯函数串联更容易表达条件边和重试；相较强调角色对话的框架，它更适合本项目确定性较强的工作流。

## 如何降低幻觉

1. 爬虫只把实际访问过的 URL 写入证据清单。
2. 字段级记录功能、定价和版本信息由哪个页面支撑。
3. JSON Schema修复格式问题，但不会把格式正确等同于事实正确。
4. Analyzer按来源数量、字段覆盖和LLM补全情况计算质量状态。
5. 没有URL证据的内容标为低置信度或推测。

## RAG的作用与边界

历史数据用于提供类似竞品的分析背景，减少重复工作。它不能替代本次采集证据；历史数据可能过期，因此最终事实仍以带时间戳的当前来源为准。

## 失败策略

- 动态浏览器不可用时尝试静态请求。
- 单个竞品失败不阻断其他竞品。
- LLM输出解析失败时进行容错解析和Schema修复。
- 官网数据不足时允许生成降级报告，但必须展示低置信度警告。

## 面试中不要夸大的内容

- 没有评测记录时，不声称固定准确率和耗时。
- 演示模式是模拟流程，不是模型效果证明。
- App Store、GitHub Release和向量检索属于实验性能力。
- 当前系统不是生产级商业尽调工具。

## 推荐现场演示

优先使用演示模式说明交互和架构，同时明确数据为模拟。若现场网络稳定，再运行一次真实模式，重点展示来源、采集时间、降级警告和失败隔离，而不是只展示最终报告。
