## 三、两处"描述超前于实现"的详细说明

### 3.1 RAG / 向量库检索（描述第 7 条）—— 实际未接通
- 证据：`agents/coordinator.py`
  ```python
  vector_store = None                      # 第 302 行，向量库被显式置空
  ...
  if vector_store is None:                 # 第 366 行，恒为 True
      logger.warning("向量库未启用...")
  else:
      doc_id = vector_store.add_competitor(data)   # 永不执行
  ```
- 后果：爬虫拿到的结构化数据**不会写入向量库**，分析阶段也**不会检索"相似竞品的历史结论"注入 Prompt**。描述中的"RAG 思路"目前只是架构设想，未落地。
- `vector_store.py`（ChromaDB 封装）本身存在，但调用方把它禁用了。

### 3.2 输出层 JSON Schema 强制约束（描述第 6 条）—— 实际不存在
- 全项目（不含 `venv/`）搜索 `jsonschema` / `JSON Schema`：无任何命中。
- LLM 输出约束方式 = Prompt 里用自然语言写"输出严格 JSON 格式"+ `safe_extract_json()` 做容错解析（处理代码块/前后文本）。
- 没有用 `jsonschema` 库对解析结果做**字段级/类型级校验**，也没有 Pydantic/JSON-Schema 的"强制约束"环节。
- 影响：当 LLM 返回的 JSON 缺字段或类型不符时，下游（`pd.DataFrame(result["matrix"])` 等）仍可能 KeyError/异常——只是被外层 `except` 兜底，不会崩但会降级。

## 六、修复记录（2026-07-09）

> 目标：把描述第 6、7 条从"架构设想"补成"代码现实"。

### 6.1 新增 `utils/json_schema.py`（输出层 Schema 强制约束）
- 定义 `PRICING_SCHEMA` / `COMPARE_SCHEMA` / `INSIGHTS_SCHEMA` 三个输出 Schema。
- `validate_and_repair(data, schema, context)`：
  - **缺失必填字段** → 按类型补默认值（如 `pricing_models→{}`、`analysis→""`），避免下游 `KeyError`。
  - **类型不符** → 强制转换（如 `analysis` 非字符串转字符串、`recommendations` 非数组包成数组）。
  - 若环境装了 `jsonschema`，再做严格校验并报告问题（用于 Bad Case 反向迭代）。
  - **不抛异常、不中断流程**：校验失败仅告警 + 修复，配合既有 `except→LLM 兜底`，保证报告始终有产出。
- `validate_string_list`：校验功能对齐等字符串数组，处理非列表/非字符串/长度不符。

### 6.2 `agents/analyzer.py` 接入
- `analyze_pricing` / `_llm_fallback_pricing` / `_llm_fallback_compare` / `generate_insights` / `_llm_fallback_insights` 在 `safe_extract_json` 之后统一接入 `validate_and_repair`。
- `_llm_align_features` 改用 `validate_string_list` 并校验返回长度。
- 上述方法新增可选 `rag_context` 参数，注入"向量库检索到的相似竞品参考"段落（向后兼容，不传则行为不变）。

### 6.3 `agents/coordinator.py` 接通 RAG
- 删除静态 `vector_store = None`，改为 `_init_vector_store()` 懒加载：
  - 用 `CompetitorVectorStore(force_lightweight=True)` —— 优先 ChromaDB 内置轻量 embedding，**零外部模型下载**，规避此前 79MB ONNX 阻塞问题。
  - 初始化失败（如未装 chromadb）则降级为 `None`，主流程不受影响。
- 修复存储循环 `doc_id` 未定义隐患；爬取成功后真正写入向量库。
- 新增 `_build_rag_context(valid_data)`：分析前对每个竞品检索相似历史竞品画像，拼成上下文。
- `_run_analyzer` 把 `rag_context` 传给 `compare_features` / `analyze_pricing` / `generate_insights`。
